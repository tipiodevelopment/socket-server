A.1 Pre-requisitos

A.2 Crear campaña





Ir a Campaigns en el dashboard



Crear campaña nueva:





Nombre: ej. "Viaplay Demo 2025"



Fechas: startDate y endDate que incluyan hoy



País objetivo: incluir NO (Noruega)



Estado: activa (no pausada)

A.3 Crear broadcast en esa campaña





En la campaña creada, pestaña Broadcasts



Clic en New Broadcast



Rellenar:





Broadcast Name: "Real Madrid vs Barcelona"



External Content ID: real-madrid-barcelona-2025-01-24 (debe coincidir exactamente con el contentId del SDK)



Start/End time: opcional



Guardar

A.4 Crear componentes (polls, contests)





En Broadcast Detail del broadcast creado, pestaña Polls o Contests



Crear al menos un poll de prueba (pregunta + opciones)



Opcional: crear contest

Parte B: SDK Implementation (Cursor)

B.1 BroadcastValidationService

Crear Sources/VioCore/Services/BroadcastValidationService.swift:





Función validate(contentId: String, country: String) async -> BroadcastValidationResult



Llamada GET /v1/sdk/broadcast?contentId=xxx&country=yyy



Headers: X-Api-Key o apiKey en query, o X-App-Bundle-ID si se usa



Modelo BroadcastValidationResult: hasEngagement, broadcastId, broadcastName, campaignId, websocketChannel, campaignComponents, broadcastComponents

B.2 VioSessionContext

Modificar VioSessionContext.swift:





Añadir contentId: String? y country: String?



Inicializador init(contentId: String, country: String, ...) para flujo contentId



Añadir useBackendEngagement: Bool (se pondrá a true cuando validación devuelva hasEngagement)

B.3 setupBroadcastContext con rama contentId

Modificar RCastingVideoPlayer.swift y RCastingActiveView.swift:





Si effectiveSessionContext.contentId != nil: llamar BroadcastValidationService.validate



Si hasEngagement: false: no llamar discoverCampaigns, no loadEngagement, no mostrar componentes de broadcast



Si hasEngagement: true: crear BroadcastContext con broadcastId de la respuesta, setBroadcastContext, discoverCampaigns, loadEngagement con useBackend: true

B.4 EngagementManager: soporte useBackend

Modificar EngagementManager.swift:





Añadir loadEngagement(for: BroadcastContext, useBackend: Bool? = nil)



Cuando useBackend == true, usar BackendEngagementRepository para esa llamada (aunque demoMode sea true)

B.5 Demo Viaplay: inyectar sessionContext para Real Madrid - Barcelona

Modificar SportDetailView.swift:





Para Real Madrid - Barcelona: crear VioSessionContext(contentId: "real-madrid-barcelona-2025-01-24", country: "NO") y pasarlo a LiveMatchView, VCastingVideoPlayer, VCastingActiveView



Para Barcelona-PSG: no pasar sessionContext (o pasar nil) para mantener el flujo actual con demo data

B.6 Barcelona-PSG: sin cambios





Match.barcelonaPSG y createMatchFromDetail() para Barcelona-PSG se mantienen



Sin sessionContext con contentId, usa match.toBroadcastContext() y demoMode (TimelineDataGenerator)
