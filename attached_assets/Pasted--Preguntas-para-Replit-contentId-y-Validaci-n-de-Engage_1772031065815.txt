# Preguntas para Replit - contentId y Validación de Engagement

Documento con preguntas para implementar en el socket-server el flujo donde la app pasa `contentId` (ID del evento/contenido) y el SDK valida si hay engagement activo antes de renderizar componentes.

---

## Contexto

- **App** (ej. Viaplay): tiene un `contentId` por cada stream/evento (partido, programa, etc.)
- **SDK**: debe validar con el backend si ese `contentId` tiene broadcast activo
- **Si hay broadcast**: cargar componentes (chat, sponsor, polls, contests)
- **Si no hay**: no renderizar nada; la app debe saberlo para ocultar botones (ej. chat)
- **Jerarquía**: App → muchas campañas → campaña tiene muchos broadcasts → broadcast tiene polls/contests
- **Componentes**: a nivel campaña (banners, carrusel, programables) y a nivel broadcast (polls, contests)

---

- **Opción B**: Tabla nueva `broadcast_content_mappings(content_id, broadcast_id, client_app_id)`
- **Opción C**: Usar `broadcasts.metadata` (JSON) para guardar `contentId`

¿Cuál prefieren? ¿O tienen otra propuesta?

## 2. Endpoint de validación

¿Crear endpoint nuevo o extender el existente?

**Opción A – Nuevo endpoint** `GET /v1/sdk/validate?contentId=xxx&country=NO`  
- Respuesta: `{ hasEngagement: true, broadcastId, campaignId, components }` o `{ hasEngagement: false }`

**Opción B – Extender** `GET /v1/sdk/campaigns` para aceptar `contentId`  
- Si viene `contentId`, resolver a `broadcastId` y filtrar por ese broadcast  
- Si no viene, mantener comportamiento actual (matchId/broadcastId)

¿Cuál encaja mejor con su arquitectura?

## Flujo objetivo (SDK)

```
App abre evento → pasa contentId + country al SDK
       ↓
SDK llama GET /v1/sdk/validate?contentId=xxx&country=NO
       ↓
Backend: ¿existe broadcast con contentId? ¿campaña activa? ¿país válido?
       ↓
hasEngagement: true  → SDK carga componentes, usa broadcastId internamente
hasEngagement: false → SDK no renderiza nada, notifica a la app
```
